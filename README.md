# JumpOne

A 2D platformer built with Phaser 3 and TypeScript, developed as the testbed for a
bachelor thesis on client-side win prediction from behavioural telemetry.
Website: https://bachelor.openpace.org/

## The thesis

**What Behavioural Telemetry Predicts Once Progress Is Held Constant: A Client-Side
Win-Prediction Pipeline for a Browser Platformer** (FH St. Pölten, 2026).

The game logs the player state every 100 ms. A gradient-boosted model trained on that
telemetry predicts, while a run is still in progress, whether it will end in
completion. The model is transpiled to plain JavaScript and runs in the browser
without a server.

The main finding is methodological. Under a row-level split the model reaches an AUC
of 0.973; under leave-one-session-out evaluation it reaches 0.868, and the gap is
session recognition rather than transferable behaviour. Once vertical progress is held
approximately constant, both the player's position and the cumulative counters fall to
chance. Behavioural telemetry contributes beyond progress only when constructed as
rates over a moving window — and that feature set is not the one the deployed client
currently computes.

## ML pipeline

| Script | Produces |
|:---|:---|
| `data_parser.py` | Parses the SQL export, propagates the label, subsamples to 500 rows per session |
| `models.py` | The nine-feature set and the three model definitions. Feature order is a contract with `Level.ts` |
| `rolling_features.py` | Rolling-window features: rates over the last 60 s instead of cumulative counters |
| `make_tables.py` | Every table of Chapters 4 and 5 from a single data build, as markdown |
| `overall_skill_distribution.py` | The principal component analysis of Section 4.6 |
| `make_figures.py` | Figures 1, 2, 3, 4, 6 and 7 |
| `make_artifact_figure.py` | Figure 5: the pre-correction model, fetched from git commit `72bf8b9` and scored with node |
| `train_xgboost.py` | Trains the models and exports XGBoost to `src/scenes/WinPredictor.ts` |

### Reproducing the results

```bash
cd ml_pipeline
pip install -r requirements.txt

# all tables of chapters 4 and 5
python3 make_tables.py --sql ../telemetry_rows_07092026.sql       # add --quick to skip window/seed sweeps

# all figures (figure 5 needs node and a git checkout)
python3 make_figures.py
python3 make_artifact_figure.py --sql ../telemetry_rows_01092026.sql

# section 4.6
python3 overall_skill_distribution.py --sql ../telemetry_rows_07092026.sql

# train and export the deployed model (overwrites src/scenes/WinPredictor.ts)
python3 train_xgboost.py --sql ../telemetry_rows_07092026.sql --max-rows 500
```

Verified with Python 3.14.3, pandas 3.0.2, numpy 2.4.4, scipy 1.17.1, scikit-learn 1.8.0,
xgboost 3.2.0, m2cgen 0.10.0, matplotlib 3.10.8, Node.js 25.8.0.

Fixed values: seed 42 for subsampling, the row-level split and model initialisation;
seed 0 with 4,000 draws for the bootstrap; 60 s window; sessions below 100 rows are
excluded, sessions above 500 rows are subsampled.

### Results in brief

Leave-one-session-out, 41 folds, session-level AUC. Majority baseline 28 of 41.

| Feature set | AUC | Sessions correct | p |
|:---|--:|:--|--:|
| `pos_y` alone | 0.923 | 38/41 | 0.0002 |
| All nine features (XGBoost, deployed) | 0.868 | 36/41 | 0.0036 |
| Cumulative features without position | 0.838 | 33/41 | 0.061 |
| Rolling behavioural features | 0.876 | 33/41 | 0.061 |

Within bands of comparable progress (start / early / middle):

| Feature set | AUC within band |
|:---|:--|
| `pos_y` alone | 0.635 / 0.489 / 0.453 |
| Cumulative, without position | 0.516 / 0.520 / 0.624 |
| Rolling behavioural | 0.802 / 0.819 / 0.803 |

`avgTimeBetweenJumps` is collected but not trained on: it counted time the game spent
paused, and 25 of the 30 trees of the June model split on it at the root, pinning the
prediction low for the rest of any run that contained a pause. The instrumentation was
corrected in September 2026 (`Level.applyJump()`).

## Running the game

[Node.js](https://nodejs.org) is required.

| Command | Description |
|:---|:---|
| `npm install` | Install dependencies |
| `npm start` | Development server |
| `npm run build` | Production build in `dist/` |

Telemetry is posted to Supabase when `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`
are set in `.env`. Without them the game runs and predicts, but records nothing.
